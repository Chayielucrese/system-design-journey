# System Design Journey

I'm a backend developer (Node.js, NestJS, MongoDB) learning system design from the beginning, and I'm doing it in public.

For 12 weeks I'm following a plan: learn a topic, build something that shows it, measure what happened, and write it up. This repo holds everything I produce along the way.

## What's inside
- **Notes:** one page per week, in my own words
- **Experiments:** small projects with before and after numbers (indexes, load balancing, caching, queues)
- **Design documents:** full designs for real projects, drawn twice: a simple version for business audiences and a detailed version for engineers

## The plan
| Weeks | Topic |

| 1 | Setup and the answer framework |
| 2-3 | Foundations: HTTP, DNS, latency, estimates |
| 4-5 | Databases: indexes, replication, consistency |
| 6-7 | Scaling and speed: load balancers, caching |
| 8-9 | Queues, retries and failure handling |
| 10-12 | Classic designs and AWS |
